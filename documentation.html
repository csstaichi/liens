3. Namecheap — le nom de domaine

Namecheap ne sert qu'à une chose ici : faire pointer csstahitimoorea.org vers Google Sites. Il n'héberge rien.

Ce qu'il faut surveiller

  • La date d'expiration. Un domaine non renouvelé cesse de répondre du jour au lendemain, et se rachète très cher pendant la période de récupération. Activer le renouvellement automatique, et vérifier que la carte enregistrée est valide.
  • L'adresse de contact du titulaire. Les avis d'expiration y sont envoyés. Si elle est celle d'un ancien membre, personne ne verra l'avertissement.
  • La protection de la confidentialité (WhoisGuard), incluse chez Namecheap. La laisser active : sinon l'adresse et le téléphone du titulaire sont publics.

Où sont réglés les enregistrements

Namecheap → Domain List → Manage → onglet Advanced DNS. C'est là que se trouvent les enregistrements qui envoient le domaine vers Google Sites.

Avant de modifier quoi que ce soit ici, faire une capture d'écran de la table complète. Une ligne effacée par erreur coupe le site, et rien n'indique ce qu'elle contenait. La propagation d'une correction prend de quelques minutes à quelques heures.
Le portail GitHub, lui, ne dépend pas du domaine. Si Namecheap tombe, csstaichi.github.io/liens/ continue de fonctionner, livre de condoléances compris. C'est une conséquence heureuse du montage, pas un hasard.

4. Google Sites — le site public

C'est le site de l'association : présentation, plannings, actualités. Il est modifiable par n'importe qui du bureau, sans code.

Ce qu'il faut savoir avant d'y toucher

  • Une modification n'est visible qu'après Publier, en haut à droite. Tant qu'on n'a pas publié, on est seul à voir ses changements.
  • Google Sites n'a pas d'historique de versions utilisable. Avant une refonte, dupliquer le site : ⋮ → Dupliquer le site.
  • Paramètres → Visibilité : ne pas laisser cochée l'option qui empêche l'indexation. Elle avait été activée par erreur et la page d'accueil n'apparaissait plus dans Google.

5. Les blocs de code intégrés

Les pages du portail sont affichées à l'intérieur du site Google, dans des cadres. C'est ce qui permet d'avoir un contenu que Google Sites ne sait pas faire, sans quitter le site.

Comment poser un bloc

  1. Ouvrir la page voulue, en mode édition.
  2. Insérer → Intégrer → onglet « Code intégré ». Surtout pas « Par URL », qui ne produirait qu'une vignette de lien.
  3. Coller le bloc, Suivant, Insérer.
  4. Étirer le cadre sur toute la largeur de la page : la largeur n'est pas fixée par le code, elle est fixée par la grille de Google Sites.

Les quatre blocs, hauteurs mesurées

La hauteur d'un cadre est figée en pixels, la même sur téléphone et sur ordinateur. C'est donc la mesure à 360 px de large qui commande, la plus haute. Sinon une barre de défilement apparaît à l'intérieur du cadre sur téléphone.

Téléverser une mise à jour

  1. Modifier les fichiers en local, jamais directement sur GitHub.
  2. Ouvrir index.html en double-cliquant, pour voir le résultat avant toute mise en ligne.
  3. Dépôt → Add file → Upload files → glisser les fichiers modifiés → Commit changes.
  4. Attendre deux à trois minutes, le temps de la publication.
  5. Recharger en vidant le cache : Ctrl+F5.
  6. Vérifier le numéro de version affiché en bas de page. S'il n'a pas changé, le téléversement n'a pas abouti.
Ne jamais glisser le dossier SITE lui-même. C'est son contenu qui monte : les cinq .html, liens.js, styles.css, et le dossier assets. Glisser SITE créerait un sous-dossier et casserait toutes les adresses.

Supprimer un fichier

Un téléversement n'efface jamais un fichier absent de l'envoi. Pour supprimer : ouvrir le fichier sur GitHub → icône corbeille → Commit changes. À faire pour assets/fond.png, assets/fond-flou.jpg et assets/motifs/bouquet.webp s'ils y sont encore.

Le dépôt est public. Tout ce qui y monte est lisible par n'importe qui, robots compris. Ne jamais y écrire d'adresse électronique en clair, de numéro de téléphone, ni de mot de passe. Aucun verrou écrit dans une page web ne restreint quoi que ce soit : le code d'une page est lisible par quiconque l'ouvre.

Point essentiel : les pages HTML ne contiennent aucun texte visible. Ce sont des gabarits. Tout ce qui s'affiche vient de liens.js. C'est ce qui permet de tout modifier en un seul endroit.

Les quatre modifications courantes

  • Changer une adresse — liens.js, bloc LIENS, ligne url.
  • Changer un texte de bouton — même entrée, lignes libelle et precision. Contrainte mesurée : precision ne doit pas dépasser 28 caractères sur les pages publique et adhérents, sinon le bouton passe de 68 à 102 px et casse le rythme.
  • Ajouter un bouton — créer l'entrée dans LIENS, puis ajouter sa clé dans JEUX.publique, JEUX.adherents ou SECTIONS. Une entrée qui n'est dans aucune liste n'apparaît nulle part.
  • Retirer un bouton — enlever sa clé de la liste. Ne pas supprimer l'entrée : elle ne gêne pas et resservira peut-être.

Le numéro de version

Déclaré une seule fois, en haut de liens.js, et affiché en bas de chaque page. Il sert à savoir d'un coup d'œil quelle livraison est réellement en ligne, sans ouvrir le code source. Sur ce dossier, une correction a été cherchée vingt minutes alors qu'elle n'avait simplement pas été téléversée.

Pourquoi l'adresse publique n'a pas de .html

Tout serveur web, quand l'adresse se termine par un dossier, y cherche un fichier nommé index.html et le sert sans le nommer. Convention universelle. C'est pour cela que la page publique doit s'appeler index.html : la renommer casserait l'adresse courte.

Modérer, au quotidien

  • Retirer un message : colonne F, écrire non. Il disparaît au rechargement suivant. Aucune livraison nécessaire.
  • Verrouiller un message : colonne G, écrire non. Le bouton « Modifier mon message » disparaît, et le guichet refuse la modification même si quelqu'un forge la requête.
  • Corriger un nom ou un texte : directement dans la cellule.
Ne jamais supprimer une ligne au milieu. Les numéros de ligne servent d'identifiant : une suppression décale tout ce qui suit, et quelqu'un dont la page est restée ouverte modifierait alors le message du voisin. Pour retirer un message, écrire non en colonne F.

L'onglet historique

Créé tout seul à la première modification. Il conserve l'état d'une ligne avant chaque réécriture : horodatage, ligne, prénom, nom, message, motif, modifiable. C'est le seul endroit où retrouver un texte écrasé. Ne jamais le supprimer.

Attention : une correction faite dans la feuille n'y passe pas. Seules les modifications venues de la page y sont archivées.

9. Apps Script — le guichet

Le projet s'appelle « CSS Livre de condoléances ». On y accède par Extensions → Apps Script depuis la feuille. Il contient deux fichiers.

FichierRôleRedéploiement ?
Code.gsle guichet : doGet lit, doPost écritoui, c'est le fichier publié
Alertes.gsles courriels d'alertenon, les déclencheurs lisent le code enregistré

Ce que fait Code.gs, et pourquoi

  • Il tourne sous le compte de l'association, pas sous celui du visiteur. C'est ce qui permet d'écrire dans la feuille sans donner à personne l'accès au Drive.
  • Verrou d'écriture. Sans lui, deux envois tombant dans la même seconde pouvaient lire la même « dernière ligne » et l'un écraser l'autre. Éprouvé : cinq envois simultanés, cinq lignes distinctes.
  • Champ piège. Un champ masqué qu'un humain ne remplit jamais et qu'un robot remplit presque toujours. S'il est rempli, le script répond « ok » sans rien écrire.
  • Le corps est envoyé en text/plain et non en application/json : c'est ce qui évite la requête préliminaire CORS, qu'Apps Script ne sait pas traiter. Le contenu reste du JSON, seul l'en-tête change. Ne pas « corriger » cela.
Un projet Apps Script partage UNE SEULE portée globale entre tous ses fichiers. Redéclarer dans Alertes.gs un nom déjà pris dans Code.gs — ONGLET, MOTIFS, COLONNES — provoque une erreur de syntaxe qui casse tout le projet, doPost compris, donc le livre entier. C'est pourquoi tous les noms d'Alertes.gs commencent par ALERTE_.

10. Déployer, et retrouver le lien

Publier une nouvelle version de Code.gs demande cinq clics, et il y en a un à ne pas manquer.

  1. Coller le nouveau Code.gs, Ctrl+S pour enregistrer. Sans cela, « Nouvelle version » figerait l'ancien code.
  2. Bouton bleu Déployer → Gérer les déploiements.
  3. Cliquer le crayon, en haut à droite du cadre Configuration. Tant qu'il n'est pas cliqué, les champs sont en lecture seule.
  4. Liste Version → Nouvelle version. Description utile : le numéro de livraison.
  5. Vérifier sans y toucher : Exécuter en tant que : Moi — Qui a accès : Tout le monde.
  6. Déployer.
NE JAMAIS CLIQUER « Nouveau déploiement ».
Cela crée une nouvelle adresse. Le portail continuerait alors d'interroger l'ancien guichet, et rien ne semblerait cassé : les anciens messages s'afficheraient encore. C'est le pire des cas, celui qui se cherche longtemps.

Retrouver l'adresse du guichet

  • Depuis Apps Script : Déployer → Gérer les déploiements → le déploiement Actif → champ URL → Copier. Ignorer ceux listés sous « Archivé ».
  • Depuis le code : liens.js, constante CONDOLEANCES_URL.
  • Elle se termine toujours par /exec. Une adresse en /dev n'est accessible qu'à vous et ne marchera pour personne d'autre.

Vérifier qu'un déploiement a abouti, sans rien installer

Ouvrir l'adresse du guichet dans un navigateur. La réponse doit contenir "ligne": devant chaque message. Si elle n'en contient pas, c'est l'ancien code qui répond.

L'adresse est écrite à DEUX endroits : SITE/liens.js (constante CONDOLEANCES_URL) et OUTILS/… export_condoleances.html (constante GUICHET). Si elle change un jour, la reporter aux deux, sinon l'outil d'export lira l'ancien registre sans afficher la moindre erreur.

11. Les alertes par courriel

Un courriel à chaque message déposé, et un courriel à chaque message modifié montrant ce qu'il disait avant. Destinataire déclaré en tête d'Alertes.gs.

Installer

  1. Apps Script → + à côté de Fichiers → Script → le nommer Alertes.
  2. Effacer le function myFunction() {} par défaut, coller le fichier, Ctrl+S.
  3. Choisir installerAlertes dans la liste des fonctions — pas alerter — puis Exécuter.
  4. Autoriser : Paramètres avancés → « Accéder à … (non sécurisé) ». L'avertissement « application non validée » est celui que Google met sur tout script personnel.
  5. Un courriel « alertes activées » doit arriver.

Ce qu'il faut savoir

  • Deux déclencheurs sont posés : onChange, immédiat mais que Google fait sauter de temps en temps, et un horaire toutes les 5 minutes qui rattrape. Les deux appellent la même fonction, écrite pour tourner à vide : aucun doublon possible.
  • Les messages déjà présents ne déclenchent rien : l'installation enregistre l'état du moment comme point de départ.
  • Une suppression de lignes ne provoque aucun courriel : le compteur se recale en silence.
  • Une correction faite dans la feuille n'est pas signalée.
  • Les règles de notification de Google Sheets ne conviennent pas : elles ne se déclenchent pas sur les écritures faites par un script. Ne pas perdre de temps à les essayer.
  • Quota d'un compte Gmail gratuit : 100 courriels par jour depuis un script.

Arrêter

Quand le livre sera clos : choisir desinstallerAlertes et Exécuter. Sinon les courriels continueront indéfiniment.

12. L'export PDF

Outil local : OUTILS/… export_condoleances.html. Il ne monte pas sur GitHub — c'est ce qui le réserve au bureau.

  1. Double-clic. Il va chercher les messages tout seul auprès du guichet.
  2. Choisir le mode. Ce choix commande la destination, voir l'encadré ci-dessous.
  3. Ctrl+P, puis dans la fenêtre de Chrome : Destination Enregistrer au format PDF, Marges Aucune, et surtout Graphiques d'arrière-plan coché.
LE MODE ET LA DESTINATION VONT ENSEMBLE.
Mesuré sur le même document, en mode « une seule page » :
destinationrésultat
Chrome — Enregistrer au format PDF1 page de 210 × 2550 mm ✔
Microsoft Print to PDF9 feuilles ✘
imprimante Lexmark CX4105 feuilles ✘
Une imprimante, réelle ou virtuelle Windows, impose son format papier et ignore la taille de page demandée. Seul le moteur PDF interne de Chrome l'honore.
Donc : une seule page uniquement avec le PDF de Chrome, pour transmettre. A4 paginé pour tout le reste, imprimante comprise — aucune carte n'y est jamais coupée.
Sans « Graphiques d'arrière-plan », le fond sombre disparaît. Mesuré : la luminance moyenne d'une page passe de 27,4 à 135,7 sur 255, et les dates deviennent illisibles. C'est l'erreur la plus fréquente.
  • Le mode continu mesure la hauteur réelle et en fait la hauteur de la page : un PDF d'une seule page, aucune carte coupée. Sur 69 messages : 210 × 2439 mm.
  • Le format PDF plafonne à 5080 mm, soit environ 112 messages. Au-delà, l'outil prévient et bascule en A4.
  • L'ordre est inverse de celui du site : le premier message déposé vient en premier. Un document se lit d'un bout à l'autre.
  • Le nom du fichier PDF est composé tout seul : 20260818 Livre de Condoléances GIROUILLE B 00.41.00 — la date du jour, le nom du registre, le numéro de version. Chrome propose comme nom de fichier le titre du document ; l'outil le compose juste avant d'imprimer, puis le remet en état.
  • L'en-tête du document porte la date, l'heure et la version. L'heure compte : un message peut arriver après l'export, et deux exports du même jour ne se distingueraient pas autrement.
  • Le manuel de reprise est nommé de même : 00.41.00 Manuel de reprise CSS Moorea Tahiti.
  • Polices et motifs sont appelés en ligne, pour que l'outil reste un seul fichier déplaçable. Sans réseau, le texte reste complet mais perd son habillage.

13. Les images pour les réseaux

Quand une adresse est partagée sur Facebook, Messenger ou WhatsApp, un cartouche s'affiche : une image, un titre, une description. Ce cartouche vient de balises posées dans la page.

PageImage d'aperçu
publique, adhérents, ressourcesassets/partage-00.37.00.jpg
planningsassets/partage-plannings-00.37.00.jpg
condoléancesassets/partage-condoleances-00.37.00.jpg
  • Format imposé : 1200 × 630 px. C'est le seul que les trois applications acceptent sans recadrer.
  • Les deux premières se refabriquent par python3 OUTILS/gen_partage.py, depuis n'importe où : le script trouve SITE tout seul. La troisième est composée à partir d'une image fournie par l'association.
  • Ne jamais faire figurer la page adhérents dans un aperçu : il circule partout.
  • Le livre de condoléances a sa propre image, sans aucun bouton. Un cartouche montrant « Boutique » et « Cotisation » sous un lien de deuil est une faute, et elle a été commise.
UNE CARTE MODIFIÉE DOIT CHANGER DE NOM DE FICHIER.
Facebook garde deux caches distincts : celui de la page, que « Re-collecter » vide, et celui de l'image, indexé sur son adresse, que « Re-collecter » ne vide pas.
Refabriquer une carte sous le même nom ne sert donc à rien : Facebook ressortira sa copie d'il y a des mois, indéfiniment, quel que soit le nombre de re-collectes. Constaté sur ce dossier, et cherché longtemps — le fichier en ligne était pourtant le bon, vérifié pixel à pixel.
C'est pourquoi les cartes portent le numéro de version dans leur nom. Après un changement : reporter le nouveau nom dans og:image et twitter:image des pages concernées, téléverser, puis re-collecter.

Forcer le rafraîchissement chez Facebook

  1. developers.facebook.com/tools/debug, connecté avec le compte administrateur de la page.
  2. Coller l'adresse, Déboguer, puis Re-collecter, une ou deux fois.
  3. À faire après le téléversement, jamais avant : sinon l'outil relit l'ancienne image et la remet en cache pour des semaines.

Deux messages du débogueur à ignorer

  • « fb:app_id manquant » — Facebook le réclame à tous les sites. Sans effet sur l'aperçu. Ne pas créer d'application pour cela.
  • « Code de réponse 206 » — particularité du serveur GitHub, qui répond par un contenu partiel. Les balises ont bien été lues.

WhatsApp — le cas particulier

L'aperçu est fabriqué par le téléphone qui envoie, pendant la frappe. Trois causes d'échec, dans l'ordre de fréquence :
  1. Message transféré : WhatsApp recopie l'aperçu d'origine et ne relit jamais la page.
  2. Publication Facebook déjà ouverte : le cartouche y est attaché. Re-collecter ne le change pas. Il faut supprimer l'aperçu par sa croix, effacer l'adresse du texte, la recoller, et attendre que le nouveau cadre se forme.
  3. Envoi trop rapide : il faut deux à cinq secondes pour que le cadre se construise. Envoyé avant, le message part sans cartouche, et c'est définitif.
  4. WhatsApp Web : échoue souvent. Utiliser le téléphone.
La bonne méthode : coller l'adresse seule, attendre que le cadre apparaisse, puis taper le texte au-dessus, dans le même message.

WhatsApp n'a pas d'outil de purge. Son cache se vide seul en quelques jours. Pour tester tout de suite, ajouter ?v=2 à l'adresse : même page, adresse neuve pour WhatsApp. Ne pas diffuser cette variante.

Une balise noindex supprime l'aperçu dans Messenger et WhatsApp : leur robot d'aperçu la respecte en supprimant le cartouche. C'est le compromis qui a fait retirer le noindex de la page adhérents. Ne pas en remettre sans savoir ce qu'on perd.

Il ne contient aucune adresse électronique, seulement des rôles. Le jour où quelqu'un a besoin de savoir quel compte détient quoi, il pose la question au président : sans les identifiants, connaître l'adresse ne sert de toute façon à rien.

Pourquoi le livre n'est lié depuis aucune page du portail

Un lien de deuil au milieu de « Boutique » et « Cotisation » n'a pas sa place. Le livre est atteignable en connaissant son adresse : lien non annoncé, pas lien secret. Le dépôt étant public et la page sans noindex, Google peut l'indexer.

La raison de fond du livre, à ne pas oublier en le reprenant : dans un groupe de messagerie, s'exprimer et déranger sont le même geste. Un message fait sonner soixante téléphones, et certains quittent la conversation. Une page, elle, ne dérange personne : on y va, elle ne vient pas. C'est pourquoi il ne faut pas relancer plusieurs fois dans les groupes — ce serait refaire sonner les téléphones que le livre servait à laisser tranquilles.

15. Mettre à jour : l'ordre

L'ordre n'est pas indifférent. Dans l'autre sens, la page neuve interrogerait l'ancien guichet, et des fonctions resteraient muettes sans qu'aucune erreur ne s'affiche.

  1. La feuille — colonnes, en-têtes, données. À la main.
  2. Le guichet — coller Code.gs, enregistrer, mettre à jour le déploiement existant.
  3. Le site — téléverser le contenu de SITE sur GitHub.
  4. Les aperçus — repasser dans le débogueur Facebook si une image ou un titre a changé.
  5. Google Sites — rallonger les hauteurs de cadre si le contenu s'est allongé.

Les numéros de version

  • Estampille d'identité — ce que le fichier prétend être : const VERSION, en-tête « Version 00.xx.00 », commentaire de première ligne. Elle monte à chaque livraison, dans tous les fichiers, même ceux dont le contenu n'a pas bougé.
  • Mention d'historique — quand une décision a été prise : « colonne portée de 460 à 560 px à la 00.18.00 ». Elle ne se réécrit jamais : c'est la mémoire du dossier.
  • Deux livraisons différentes ne portent jamais le même numéro.
  • Les fichiers dont le nom n'est pas écrit en dur dans le code portent le numéro dans leur nom : le CSV, l'outil d'export. Les fichiers de SITE, dont les noms sont écrits dans le code et dans les adresses, le portent dans leur en-tête.

16. Les neuf contrôles avant chaque mise en ligne

  1. Syntaxe — JavaScript et Apps Script vérifiés, console du navigateur vide.
  2. Fichiers de configuration — sans objet sur ce projet.
  3. Balises — le bon nombre de boutons, de cartes et de vignettes s'affiche.
  4. Identifiants perdus — aucune clé disparue par rapport à la version précédente.
  5. Rendu à 360 et 1280 px — mesuré et regardé à l'œil : une mesure de hauteur ne voit pas une couleur cassée.
  6. Ressources — dans les deux sens : chaque ressource appelée existe, et chaque ressource présente est appelée.
  7. Livré = dossier de travail.
  8. Taille du zip.
  9. Cohérence des numéros et santé des documents — python3 OUTILS/verif_versions.py 00.37.00, quatre passes, rend 0 si tout passe.

17. Évolutions possibles

Cloudflare devant le domaine

Gratuit. On délègue les serveurs de noms de Namecheap à Cloudflare, puis on gère tout depuis Cloudflare.

  • Ce que ça apporte : certificat automatique, cache mondial donc chargement plus rapide depuis la Polynésie, protection contre les attaques, statistiques de fréquentation sans mouchard, et surtout des redirections — par exemple csstahitimoorea.org/liens vers le portail GitHub.
  • Ce que ça coûte : une brique de plus à comprendre, et un point de panne supplémentaire. Une erreur de réglage coupe le site.
  • Le piège : ne PAS activer le proxy (nuage orange) sur les enregistrements qui pointent vers Google Sites. Google sert son propre certificat ; le proxy provoque une boucle de redirections. Laisser ces lignes en « DNS only ».
  • Ce que ça ne change pas : le portail resterait sur GitHub. Cloudflare ne ferait que fabriquer une adresse plus courte.
Si un jour le portail est servi sous le domaine de l'association, la règle de fond du montage tombe : l'adresse trahirait le site. Ce serait acceptable pour les plannings et les ressources, jamais pour la page publique.

Namecheap — autres options

  • Redirection d'URL incluse : Namecheap sait à lui seul rediriger liens.csstahitimoorea.org vers le portail, sans Cloudflare. Plus simple, mais sans cache ni statistiques.
  • Adresses de courriel au domaine, du type adressefonctionnellespersonnalisees.org. Payant, et impose de déplacer les enregistrements MX. À ne faire que si le bureau change souvent de main.

Domaine propre pour le portail

GitHub Pages accepte un domaine personnalisé : Settings → Pages → Custom domain, plus un fichier CNAME à la racine du dépôt. Gratuit, certificat automatique. Utile si csstaichi.github.io devait un jour disparaître.

Le livre au-delà de l'événement

  • Le clore : lancer desinstallerAlertes, puis retirer le formulaire de dépôt en laissant les messages visibles.
  • L'archiver : produire le PDF continu, le déposer dans le Drive de l'association, et le mentionner dans le compte rendu d'assemblée.
  • Le réutiliser : le montage est réutilisable tel quel pour un autre décès. Créer une nouvelle feuille et un nouveau projet Apps Script, jamais réutiliser ceux-ci : les messages de deux deuils ne se mélangent pas.

18. Redémarrage à froid — la liste de reprise

Quelqu'un qui reprend le dossier sans rien connaître, dans l'ordre :

  1. Lire le MEMO_PORTAIL du zip le plus récent. C'est la notice de référence.
  2. Lire la PASSATION du même zip : elle dit ce qui est fait, ce qui ne l'est pas, et pourquoi.
  3. Ouvrir https://csstaichi.github.io/liens/ et noter le numéro de version en bas de page. C'est la livraison réellement en ligne.
  4. Ouvrir l'adresse du guichet dans un navigateur : si la réponse contient "ligne":, le guichet est à jour.
  5. Ouvrir la feuille, vérifier les sept colonnes et l'onglet historique.
  6. Vérifier dans Apps Script qu'il n'existe qu'un seul déploiement actif.
  7. Vérifier la date d'expiration du domaine chez Namecheap.
  8. Vérifier que les identifiants des trois comptes sont connus d'au moins deux personnes.

Les quatre pièges qui ont réellement coûté du temps

  1. Une correction cherchée vingt minutes alors qu'elle n'avait pas été téléversée. Toujours vérifier le numéro en bas de page.
  2. Un guichet resté à l'ancienne version : les messages s'affichaient, mais les motifs étaient tous remplacés par « ? » et les boutons de modification absents. Rien ne semblait cassé.
  3. Un aperçu WhatsApp absent parce que le message avait été transféré, et non écrit.
  4. Un fichier image resté dans assets sans être appelé nulle part, monté sur GitHub à chaque téléversement pendant plusieurs livraisons.
